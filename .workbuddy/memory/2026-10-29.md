# 2026-10-29

## PDF 导出 500「Not a supported font format」结案

- 根因:pdfkit `registerFont(name, src, family)` 的第三个参数被 fontkit 当 **PostScript 名**在 TTC 集合内逐字面精确比较;老候选表传 `Noto Sans CJK SC` / `WenQuanYi Zen Hei` 等显示名,全部返回 null,再被包装成该错误。Windows 首个候选 `simhei.ttf` 是单体 TTF,永远不触发,故本地正常。
- 叠加:`.env` 的 `REPORT_FONT_PATH` 因 import 求值早于 `loadEnvFile` 从未生效;`doc.font()` 在 try 外,错误被吞成 `internal_error`。
- 修复:`server/src/report/fonts.ts` 改惰性收集(REPORT_FONT_PATH → 项目 `fonts/` → 系统字体 → fc-match)+ fontkit 自省取 PostScript 名 + 校验中文字形;新增 `server/src/env.ts` 并在 `index.ts` 首行 import;启动日志打印实际字体;新增 `pnpm check:font`。
- 已证实:CFF 可嵌入(NotoSansCJKsc-Regular.otf 实测),`unicode-properties@1.4.0` 的 exports 拼写错误不是本次来源。旧交接文档已改写为复盘。
- 提交:`b8e3d36`(fix)、`0f8d01d`(docs)、`312b563`(deploy),已 push。
- 遗留:未实机验证 `NotoSansCJK-Regular.ttc`(CFF-in-TTC)嵌入,服务器主路径是 `fonts/simhei.ttf`,若报 `report_font_invalid` 换 ttf 即可。
