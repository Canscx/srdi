# 2026-10-28

## 完成:专精特新申报打分网站第一阶段

**背景**:用户要做"上传企业资料自动打分"的网站。原以为 DeepSeek API 不支持图片,实际 V4.1 Flash(`deepseek-flash`)已原生多模态,1M 上下文,单图 ≤384 tokens。

**核心判断**:AI 只抽证据、写建议;分数由纯函数规则引擎算。理由:可复现、可追溯、可校准,模型直接给分三条都做不到。

**政策发现**:2026-04-01 起新版《优质中小企业梯度培育管理办法》(工信部企业〔2026〕2号)生效,旧的"满分100分/60分及格"评分表已废止。现行是六项门槛 + 23 项指标(5 维度:专业化15/精细化20/特色化15/创新能力35/成长性15),得分须 ≥50。旧的 100 分表在网上仍大量流传,是常见坑。

**关键约束**:23 项里 8 项依赖"行业均值"(约 32 分),官方均值由培育平台后台匹配,第三方拿不到。2 项 C 类(专利点度中心度、细分行业排名)完全不可得。所以产品定位是"门槛预检 + 差距诊断 + 补强路线图",不是"官方同款分数"。

**已交付**(全部通过 ajv 校验,已 commit + tag v0.1.0):
- `config/rules/rules.srdi.v1.0.0.json` — 六门槛 + 23 指标完整参数
- `config/catalog/field-catalog.v1.json` — 40 字段含表头别名
- `config/benchmarks/industry-benchmarks.v1.2.0.json` — 14 行业 + default
- `shared/schema/` — 5 份 Schema(rules/field-catalog/benchmarks/evidence)
- `docs/` — 三篇(architecture/scoring/pipeline),刻意压缩到 450 行内
- `README.md` / `PROGRESS.md`(含 10 条决策记录)/ `.gitignore` / `.gitattributes`

**用户偏好补充**:明确要求文档要薄,"字数太多占用 AI 上下文"。原计划 7 篇已砍到 3 篇,40 字段信息全部下沉到 field-catalog.json 的 description 字段,不再单写 markdown。

**技术栈**:Vue3 + TS + Vite + Element Plus + Express 5 + 纯文件系统存储。后端选 Node 而非 Python,决定性理由是打分引擎需前后端共享以便调参实时重算。止损点:3 份实测 pdfjs 表格准确率 <70% 即换 Python。
