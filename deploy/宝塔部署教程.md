# 宝塔部署教程 · 手把手版

从"服务器还是空的"到"浏览器打开域名看到登录页"。每一步都带验证点,做完一步确认一步,不要跳。

参数速查与原理说明见同目录 `README.md`。

## 0. 部署前清单

| 项 | 要求 | 没有它会怎样 |
| --- | --- | --- |
| 服务器 | 2 核 4G 起,已装宝塔面板 | 2G 内存解析大 PDF 会直接崩 |
| 域名 | 已购买并解析到服务器 IP | 只能用 IP:端口访问 |
| 备案 | 国内服务器必须备案;境外(如腾讯云新加坡)不用 | 备案没下来 80/443 被拦 |
| 宝塔插件 | Node 项目管理器(网站 → Node项目) | 找不到添加入口 |

检查域名解析:本地终端 `ping 你的域名`,返回服务器 IP 即通过。

## 1. 上传代码

宝塔「终端」里执行(推荐 git,以后更新一条命令同步):

```bash
cd /www/wwwroot
git clone <你的仓库地址> srdi
cd srdi
```

用 zip 上传也行,但**压缩包里绝不能包含** `node_modules`、`data`、`release`、`.tmp` —— 前两个几百 MB 且跨机器必坏,后两个属于本机私有产物。

验证:`ls /www/wwwroot/srdi` 能看到 `server`、`web`、`package.json`。

## 2. 安装 Node 22 与 pnpm

宝塔 → 软件商店 → Node.js 版本管理器 → 安装 **v22**(LTS)。

**不要用 v26 或更新的 Current 版本。** 项目里 `@napi-rs/canvas` 是预编译二进制,新 ABI 未必有对应包,`pnpm install` 当场报错。22 是经过完整验证的版本。

```bash
node -v          # 应显示 v22.x
npm i -g pnpm
pnpm -v          # 应显示 11.x
```

## 3. 安装依赖并构建

```bash
cd /www/wwwroot/srdi
pnpm config set registry https://registry.npmmirror.com   # 国内加速,可选
pnpm install
pnpm build
```

三条纪律:

1. `pnpm install` **不能加 `--prod`** —— `tsx` 在 devDependencies 里,过滤掉服务起不来
2. `pnpm build` 必须出现 `✓ built in` 字样
3. 构建后 `ls web/dist` 应看到 `index.html`

## 4. 安装中文字体

导出 PDF 需要中文字体,三选一:

**A. Ubuntu / Debian**

```bash
apt install -y fonts-noto-cjk
```

**B. RHEL / CentOS / OpenCloudOS / 麒麟**

```bash
dnf install -y wqy-zenhei-fonts
```

**C. 直接放字体文件**(没有包管理器权限时最稳)

宝塔「文件」进入 `/www/wwwroot/srdi`,新建 `fonts` 目录,把 `simhei.ttf` 传进去即可,不用配环境变量。

装完做一次自检,它会列出所有候选并真的生成一张中文 PDF:

```bash
cd /www/wwwroot/srdi
pnpm check:font
```

看到「结论 PDF 导出可用」才算这一步完成。`.ttc` 字体由程序自动读内部的 PostScript 名,不用手填字体族名。改完字体重启 Node 项目生效。

## 5. 配置登录密码

在项目根目录创建 `.env` 文件(宝塔「文件」里右键新建,或命令行):

```
AUTH_USER=admin
AUTH_PASSWORD=改成你的密码
```

这就是登录页的账号密码。不建 `.env` 也能跑,走内置默认值;**建议一定改掉默认密码再开放访问**。

## 6. 宝塔添加 Node 项目

网站 → Node项目 → 添加Node项目,逐项填写:

| 字段 | 填什么 | 说明 |
| --- | --- | --- |
| 项目目录 | `/www/wwwroot/srdi` | 指到代码根目录,不是 /www/wwwroot |
| 项目名称 | `srdi` | 之后日志里用 |
| 启动选项 | 自定义命令:`node_modules/.bin/tsx server/src/index.ts` | 见下方「两个必改」 |
| Node版本 | v22 | 不要用默认的 v26 |
| 包管理器 | pnpm | |
| 不安装node_module | **勾选** | 第 3 步已装好,让宝塔再装会出岔子 |
| 运行用户 | www | 默认 |
| 项目端口 | `8787` | 服务真实监听端口 |
| 绑定域名 | 你的域名 | 会自动生成反代 |

**两个必改的默认值:**

- **启动选项别选"自动获取"**。它会执行 `pnpm build && ...`,以后每次重启都重新构建前端,失败一次整个服务起不来。自定义命令只负责拉起进程。
- **Node 版本别用 v26**。理由见第 2 步。

点确定后看项目状态变「运行中」。如果启动失败,点项目日志,九成是 Node 版本或依赖没装全。

## 7. 验证服务活着

```bash
curl http://127.0.0.1:8787/api/health
```

返回 `{"ok":true,...}` 即成功。此时浏览器打开域名,应该能看到**登录页**——是的,现在就能登录进系统用了。

剩下的步骤是修正体验与补上证书,不完成也能跑,但别省。

## 8. 修正反向代理

宝塔自动生成的反代缺两样东西:

- 上传 50MB 的 PDF 会报 413(nginx 默认只放行 1MB)
- 解析进度条永远不动(SSE 被缓冲了)

网站 → 设置 → 配置文件,找到 `#PROXY-START/` 到 `#PROXY-END/`,**整段替换**为本项目 `deploy/nginx-site.conf` 的内容,然后:

```bash
nginx -t && nginx -s reload
```

替换后验证:登录 → 上传一份样本材料 → 点解析 → **进度条会动**。

**不要用面板的「加密访问」「反向代理」按钮改这块** —— 前者会让反代失效(输完密码白屏),后者会覆盖你手改的配置。访问保护已内置在登录页里,nginx 层不用再加任何密码。

## 9. SSL 证书

网站 → 设置 → SSL → Let's Encrypt → 勾选域名 → 申请 → 开「强制 HTTPS」。

登录密码虽然不走在 URL 里,但不加密的连接依然能被会话劫持。强制 HTTPS 是硬要求,不是锦上添花。

## 10. 日常更新

本地改完代码后:

```bash
pnpm validate     # 本地,提交前必跑
git push
```

服务器上一条命令:

```bash
bash deploy/update.sh
```

脚本会依次拉代码、同步依赖、构建前端、跑一次 `pnpm check:font` 确认 PDF 字体仍可用,再重启服务。

它会自动:拉代码 → 同步依赖 → 构建前端 → 重启服务 → 健康检查。全程约一分钟,数据不受影响。

改了 `config/` 目录(规则参数、行业基准)要留意:评分口径会变,已出的报告和新打分会不一致。

## 11. 数据备份

所有项目、材料、打分结果都在 `/www/wwwroot/srdi/data` 一个目录里。

宝塔 → 计划任务 → Shell 脚本,每天凌晨执行:

```bash
tar -czf /www/backup/srdi-$(date +\%F).tar.gz -C /www/wwwroot/srdi data
find /www/backup -name "srdi-*.tar.gz" -mtime +7 -delete
```

保留最近 7 天,自动清理更早的。

## 12. 排错速查

| 现象 | 原因 | 处理 |
|---|---|---|
| Node 项目启动即停 | 用 `--prod` 装了依赖 | 重跑 `pnpm install` 再重启 |
| 登录页之后白屏 | 用了面板「加密访问」 | 删掉它,重套 `nginx-site.conf` |
| 传 PDF 报 413 | 反代没改 | 做第 8 步 |
| 进度条不动 | SSE 被缓冲 | 做第 8 步 |
| 导出 PDF 报 500 `report_font_missing` | 缺字体 | 做第 4 步,再 `pnpm check:font` |
| 导出 PDF 报 "Not a supported font format" | 旧版本的字体名解析缺陷 | 拉最新代码重启,再 `pnpm check:font` |
| 登录一直失败 | 密码不对或 Cookie 被拦 | 核对 `.env` 的 `AUTH_PASSWORD`,清浏览器 Cookie |
| 域名打不开 | 备案或解析问题 | `ping 域名` 看解析;国内服务器查备案 |

更多细节(原理、取舍、架构边界)见 `deploy/README.md`;改动记录见根目录 `PROGRESS.md` 的「决策记录」。
